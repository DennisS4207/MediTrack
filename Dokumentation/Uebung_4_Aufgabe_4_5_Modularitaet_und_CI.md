# Übung 4 – Aufgabe 5: Modularität und Testbarkeit via CI/CD

Der Code ist nach Domain-Driven Design in fünf Bounded Contexts gegliedert (Benutzerverwaltung, Patientenverwaltung, Vitaldatenüberwachung, Alarmmanagement, Behandlungsdokumentation), die jeweils die Schichten `domain`, `application` und `infrastructure` besitzen. Die Contexts importieren sich nie gegenseitig und verweisen nur über IDs aufeinander, zum Beispiel über die `patient_id`. Die Domäne kennt weder die Application-Schicht noch die Infrastruktur noch Frameworks, und die Services arbeiten ausschließlich gegen Repository-Schnittstellen. Dadurch lässt sich jeder Anwendungsfall mit In-Memory-Repositories ohne Datenbank und Webserver testen. Diese Regeln prüft der Test `test_architektur.py` automatisch per Analyse der Importe, sodass ein Verstoß die Pipeline fehlschlagen lässt. Die CI läuft über GitHub Actions bei jedem Push und bei Pull Requests gegen `main`. Sie installiert die Abhängigkeiten, prüft den Code mit flake8 und führt die Architektur-Tests aus. Danach laufen alle Tests mit `pytest`, parallel unter Python 3.10, 3.11 und 3.12. Ein Build schlägt fehl, wenn die Code-Abdeckung unter 90 % fällt, und die Ergebnisse werden als Artefakt gespeichert. So wird jede Änderung geprüft, bevor sie nach `main` gemerged wird.
